    Events

    Everything the engine does is published as an event on its event bus: each step of a question, its result manifest, its answer as it is written, and how it ended; and, as Wave A lands, model calls, policy denials, hook decisions, index builds, purges and LLM swaps. Two readers see them:

    • The caller who asked the question sees their own run's events on engine.stream_query, from a caller-safe allow-list. nl2sql-api's POST /query/stream, the playground and nl2sql run all read this stream.
    • An operator sees every event of every run, and the engine's own, through engine.events.subscribe.

    The design is Wave A, section 3.

    The event

    from nl2sql import Event   # nl2sql_sdk.events.Event: pydantic and the standard library only

event.name       # "node.finished", from the catalog
event.at         # when, in UTC
event.trace_id   # the run's id (QueryResult.trace_id); None for an engine event no run caused
event.tenant_id
event.data       # JSON-ready; the catalog's model for this name
event.sse()      # "event: <name>\ndata: <the whole event as JSON>\n\n"

    trace_id is the id a run has everywhere: the result (QueryResult.trace_id), its saved results (engine.results.page), its trace (engine.traces.get) and its log lines all join on it.

    No event carries result rows, sample values, keys or header values. The question and the answer text are carried, and may contain values from the data.

    The catalog

    engine.events.catalog() lists every event: its name, description, whether a run has it (run), whether the caller's stream carries it (stream), whether the audit observer writes it (audit, narrowed by audit_only to some values of a field: of hook.decision, only deny, needs_approval, approved and error) and its data's JSON Schema (data_schema). The catalog lives in nl2sql/events/catalog.py; a name that is not in it cannot be published.

    Run events (they carry the run's trace_id):

    Name Data On the stream
    run.started question, user_id, tenant_id, roles, datasource_id, execute yes
    node.started node, sub_query_id yes
    node.finished node, sub_query_id, seconds, ok yes
    answer.delta field (summary, content), text yes
    result.manifest results: each saved result's node_id, columns, row_count, truncated, column_kinds yes
    sanity.flagged code, sub_query_id, retry yes
    run.limit_reached limit, value, spent yes
    run.finished a summary, never rows: status, duration_s, usage, error_codes, source, datasources, tables (datasource.schema.table), result_manifest, user_id, roles yes, with result added
    run.failed message (a key in it redacted), error_code, user_id, roles yes
    llm.call node, agent, model, the six token counts, latency_s, cost, usage_reported, error (redacted) no
    llm.parse_retry agent, schema, attempt (1 for the first retry), errors (the validation messages only, never the model's answer) no
    plan_cache.lookup datasource_id, hit no
    policy.decision a denial: datasource_id, schema, table (both None for a datasource), rule, step (logical_validator, curated_matcher or datasource_resolver) no
    hook.decision hook, point, decision, reason, ... no
    knowledge.used sub_query_id, datasource_id, terms (name to match score), rules (ids), dropped, digest no; not yet published (Wave B's K2)
    clarification.requested sub_query_id, phrase, options (how many) no; published by the clarifier when a run ends needs_clarification
    cost.estimated datasource_id, sub_query_id, estimated_rows, cost, limit, decision (allow, confirm, refuse; the audit observer writes confirm and refuse) no; published by the policy.cost hook when a cost limit applies, once per sub-query's SQL (an approved re-run asks again)

    Engine events carry no trace_id: they happen outside any question and go on the engine's bus directly.

    Name Data Published when
    datasource.failed datasource_id, stage, message, fix a connection check fails: the engine's start, engine.check() and engine.datasources.test() (by id, or with a Datasource it builds and tests)
    index.started datasource_id, namespace engine.index.build starts one datasource
    index.column_failed datasource_id, table, column, stage, message one per issue the adapter reported (a column it could not profile, a table it could not reflect): the issue only, never the column's statistics or sample values. For the values and profile stages, whose driver message may quote a value, message is a fixed sentence and the error's type
    index.swapped datasource_id, namespace, build_id, schema_version, replaced_build_id, replaced_schema_version, counts (entries by type) a datasource's new build goes live (audited)
    index.failed datasource_id, reason one datasource's build fails; its previous build stays live
    schema.drifted datasource_id, from_version, to_version (None for the live database), detected_by (check or build), the whole diff's counts; never a table name engine.index.check() finds the live database differs from its build (once per drift per engine, not on every check), or a build stores a structural diff (audited). See Schema Drift
    retention.purged counts: what engine.storage.purge() returned (traces, results, proposals, audit) engine.storage.purge() ran (audited)
    llm.changed by, changes (never a key) engine.llm.replace (audited)
    eval.case, eval.finished see Evals engine.evals.run
    knowledge.loaded sources (type, counts, sha256), digests per datasource, error the engine is built with a knowledge section, and engine.knowledge.reload() (with error when the reload failed and the previous knowledge stayed live). See Knowledge
    profile.finished datasource_id, the report's counts, stopped_by, cost, seconds engine.knowledge.profile finished one datasource (counts only, never a name or a value). See Schema Profiler
    proposal.created id, kind, datasource_id, origin a new proposal entered the review queue (a thumbs-up, or another track's finding)
    proposal.decided id, kind, datasource_id, decision, by, wrote engine.proposals.accept or reject decided one (audited)

    Release 0.9 (Wave C) adds the events below. They are catalogued now; the change named with each publishes it. None is on stream_query's allow-list: conversations.stream adds the two conversation events to its own. The three marked turn belong to a conversation turn, which opens a scope of its own and so has a trace_id; none carries rows, a value of an argument, or a token.

    Name Data Published when
    conversation.started conversation_id, user_id, datasource_id engine.conversations.start (C1)
    conversation.step (turn) conversation_id, turn, tool, status, trace_id (an ask step's), args (argument names only) the model's loop finished one tool call (C1)
    conversation.turn (turn) conversation_id, turn, kind, status, trace_id, steps, stored (the stored Turn as JSON, on the conversation stream only) a turn was stored (C1)
    chat_tool.called (turn) tool, conversation_id, turn, ok, seconds, error_code a registry chat tool ran, in the model's loop or by name; in the turn's scope (C2)
    dashboard.generated dashboard_id, datasource_id, tiles, skipped engine.dashboards.generate (D3)
    dashboard.refreshed dashboard_id, trigger, counts (charts per status), filters (ids, never values) a refresh, an open that refreshed, or a scheduled run (D2)
    dashboard.changed dashboard_id, change (the edit kinds, a move being the kind move; pinned; deleted; created, a new draft), by an edit, a pin, a delete or a new draft (D1, D4)
    dashboard.schedule_set dashboard_id, every_minutes, by a schedule was set; it saves a role snapshot (audited, D1)
    dashboard.schedule_stopped dashboard_id, reason a schedule stopped with a visible error (audited, D2)
    workspace.changed workspace_id, change (created, renamed, deleted), by engine.workspaces (D1)
    datasource.saved datasource_id, file, by engine.datasources.save wrote one datasource file (file is datasources/<id>.yaml; audited)
    api_key.created, api_key.revoked key_id, user_id, tenant_id, roles, by (on revoke, user_id is whose key it was); never the token engine.api_keys.create and revoke (audited); revoking an already revoked key publishes nothing
    mcp.denied reason (missing, malformed, unknown, revoked), key_id nl2sql mcp --http refused a bearer token: no header, a malformed token, an unknown key or a revoked one (audited; never the token)

    The driver and exception text in datasource.failed (message, fix), index.failed (reason) and index.column_failed (message) is redacted as a trace is: every secret the engine knows of, and every secret-shaped substring, such as the password in scheme://user:password@host or user:password@host and a password=... pair, becomes [REDACTED].

    policy.decision is published for denials only, and only where a refusal is enforced (the logical validator refusing a table of the plan, the curated matcher refusing a verified query, the datasource resolver refusing every datasource it was asked about). The validator publishes a refused table once per check, even when the plan names it twice. A scope asked only to filter (routing that skips some datasources, the schema retriever, the value check) publishes nothing, so the bus is not flooded with tables nobody asked for. Every catalogued event is published today except run.limit_reached, whose Wave A PR is named in its description. While a hook is attached at answer.after, a run publishes no answer.delta and sends result.manifest only after the hooks allowed the answer (never, on a deny).

    The run's stream

    from nl2sql import NL2SQL, UserContext

engine = NL2SQL.from_config("nl2sql.yaml")
for event in engine.stream_query("Which genre sells the most tracks?",
                                 user_context=UserContext(roles=["analyst"])):
    if event.name == "node.started":
        print("running", event.data["node"])
    elif event.name == "answer.delta":
        print(event.data["text"], end="", flush=True)
    elif event.name == "run.finished":
        result = event.data["result"]   # what run_query returns, as JSON
    elif event.name == "run.failed":
        print("could not run:", event.data["message"])

    The stream yields its own run's events, in the order they were published, from the allow-list: run.started, node.started, node.finished, answer.delta, result.manifest, sanity.flagged, run.limit_reached, and then exactly one of run.finished or run.failed.

    • The stream is the caller's, so it carries only what the caller may see. A policy.decision would tell a denied user which table exists, and hook.decision, llm.call and plan_cache.lookup are operator data. They reach an operator through engine.events.subscribe only.
    • The terminal event holds the result, on the stream only. The stream's run.finished is the bus event's summary plus data.result, the QueryResult as JSON. The event published on the bus never has it.
    • A failure inside the pipeline is still run.finished. A refusal, a provider error, a timeout or a cancel ends in run.finished with status: "error", exactly as run_query returns it. run.failed means the run could not start or crashed outside the pipeline.
    • Exactly one terminal event, whatever breaks. A failure the run's own run.failed could not report (an interrupt, a crash after the run's summary was published) still ends the stream with a run.failed carrying the run's trace_id.
    • Closing the iterator early cancels the run before its next step or model call.

    As Server-Sent Events, each event is event: <name> and one data: line holding the whole event as JSON. That is what nl2sql-api's POST /api/v1/query/stream (REST) and the playground's /api/ask/stream send.

    The allow-list is one definition: the catalog entries marked stream (nl2sql.events.STREAM_EVENTS). An event a later release adds joins the stream by its catalog entry alone.

    Subscribing: the operator's view

    def show(event):
    print(event.at, event.trace_id, event.name, event.data)

subscription = engine.events.subscribe(show)                         # every event
denials = engine.events.subscribe(show, names=["policy.decision"])   # some
...
subscription.close()

    engine.events.subscribe(fn, names=None) calls fn for every event the engine publishes, every run's and the engine's own, or for names only (a name not in the catalog is a ValueError). fn is a function of one Event, or an Observer (nl2sql.Observer): an object with on_event, whose own events choose its names when names is not given. Subscription.close() detaches it.

    • Synchronous. fn is called on the thread that published the event, which may be one of a run's worker threads, before the run goes on. A slow subscriber slows the run; an observer that keeps state locks it.
    • Fails open. An exception from fn is caught and logged once per subscriber and event name, at WARNING, on the nl2sql.events logger; it never fails a run.
    • One bus per engine. Two engines in one process share no subscriber.

    The engine's own observers (log, audit, otel and plugins) subscribe the same way, from the observers section: see Observers.

    Logs carry the run's trace_id

    Every log line written while a question runs carries its trace_id and tenant_id, on the caller's thread and on every graph worker thread, so a trace, its events and its log lines join on one id. nl2sql, nl2sql demo and nl2sql-api configure logging with the filter that adds them (--log-format json, or NL2SQL_LOG_FORMAT=json, writes them as fields). A library caller who configures logging their own way adds nl2sql.TraceContextFilter to their handler:

    import logging
from nl2sql import TraceContextFilter

handler = logging.StreamHandler()
handler.addFilter(TraceContextFilter())
handler.setFormatter(logging.Formatter("%(asctime)s [%(trace_id)s] %(name)s %(message)s"))
logging.getLogger().addHandler(handler)

    The trace

    A run's trace lists its events (every one but answer.delta) under events.
