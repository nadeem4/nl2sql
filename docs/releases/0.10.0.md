# NL2SQL 0.10.0

<!-- summary:start -->

A new product surface: a React web app served by `nl2sql-api`, a full v1 REST API behind it, a `nl2sql chat` terminal app, and the CLI in its own package, `nl2sql-cli`. Saved answers, a guided dashboard builder and stored approvals come with them. The `nl2sql` command now needs `nl2sql-cli`, so read Upgrading before you install it.

<!-- summary:end -->

*Released 2026-11-03.*

## Highlights

- **A web app.** One React app (`nl2sql-ui`) is built into `nl2sql-api` and served from the same process, so installing needs no Node. It has chat with clarifying questions, approvals and "why this answer", dashboards in workspaces, connect, knowledge review and drift pages, evals, settings and a start screen. The old playground is gone.
- **A full v1 REST API.** Routes for queries, results, traces, conversations, dashboards, workspaces, datasources, the index, knowledge, evals, settings and API keys under `/api/v1`, with server-sent events, background jobs, per-request model overrides, one error envelope and caller identity. In hosted demo mode each visitor gets a signed session.
- **Saved answers and a guided dashboard builder.** "Did this answer it?" saves an answer to a personal list and proposes it for review. The builder turns saved answers and curated queries into a dashboard you tick tile by tile. Approvals can be stored as grants tied to a request id.
- **The CLI in its own package, and a terminal app.** `nl2sql-cli` carries the `nl2sql` command, which depends on the engine and Textual, and adds `nl2sql chat`. This is the first release of `nl2sql-cli` on PyPI.
- **Try the demo, and one deployment.** A replay provider runs the demo with no model key. One API image and a compose stack serve the demo, your data or the hosted demo, chosen by `mode:` or `NL2SQL_MODE`.
- **A restructured docs site.** Get started, Use it, Configure, Deploy and operate, Extend, Reference, How it works and Contribute, with `SECURITY.md` and `CODE_OF_CONDUCT.md`.

## Benchmarks

The Chinook retrieval baseline is re-recorded on 2026-11-03: column recall 91.2%, table recall 99.2%. The Pagila baseline is unchanged. See [Benchmarks](../benchmarks.md).

## Known limits

- The web app and the REST API serve one project per process. There is no multi-project platform.
- The hosted demo's limits are not hardened against deliberate abuse.
- The hosted demo's recorded chat includes questions its `viewer` role cannot answer.

## Upgrading

```console
pip install --upgrade "nl2sql-engine==0.10.0"
pip install "nl2sql-cli[web]==0.10.0"
```

Third-party adapter and store authors: `pip install "nl2sql-sdk==0.10.0"`.

Breaking changes: several. Each needs a look before you upgrade.

- **The `nl2sql` command now comes from `nl2sql-cli`** ([#439](https://github.com/nadeem4/nl2sql/pull/439)). `nl2sql-engine` no longer installs it, and its `nl2sql.cli` package is gone. The command is still `nl2sql`. *What to do:* `pip install nl2sql-cli`, or `pip install "nl2sql-cli[web]"` to also run `nl2sql demo` and `nl2sql serve`, which start `nl2sql-api` as a child process. Code that imported `nl2sql.cli` should call the engine facade.
- **The `demo` extra of `nl2sql-engine` is gone** ([#438](https://github.com/nadeem4/nl2sql/pull/438)). The web app ships inside `nl2sql-api`. *What to do:* replace `nl2sql-engine[demo]` with `nl2sql-cli[web]`.
- **`settings.feedback` is removed** ([#446](https://github.com/nadeem4/nl2sql/pull/446)). Nothing read it. A config that sets it now fails with `settings.feedback: Unknown key.` *What to do:* delete the `feedback:` block under `settings:`. Ratings are still stored and `nl2sql feedback` still works.
- **The REST routes moved** ([#404](https://github.com/nadeem4/nl2sql/pull/404), [#414](https://github.com/nadeem4/nl2sql/pull/414), [#415](https://github.com/nadeem4/nl2sql/pull/415), [#405](https://github.com/nadeem4/nl2sql/pull/405)). Datasource routes are plural (`/api/v1/datasources`, was `/datasource`), results are read under `/api/v1/results/` (was `/query/{request_id}/results/{result_id}`), and indexing runs as a background job (`POST /api/v1/jobs/index`, was `/index/{id}` and `/index-all`). Errors use one envelope. *What to do:* update REST clients to the routes in the [REST API reference](../api/rest/index.md).
- **Traces and ratings belong to the asker** ([#407](https://github.com/nadeem4/nl2sql/pull/407), [#414](https://github.com/nadeem4/nl2sql/pull/414)). A caller who did not run a query cannot read its trace or rate it, and a trace redacts withheld rows and operator config for non-operators. *What to do:* pass the asker's identity when reading a trace.
- **The hosted demo's session cookie is no longer the user id** ([#428](https://github.com/nadeem4/nl2sql/pull/428)). Sessions are signed with a key kept as `hosted_session.key` under `storage.path`. *What to do:* nothing; visitors start a new session.
- **New optional config keys:** a top-level `mode:` (`demo`, `your_data` or `hosted`) and an `api:` file include for `nl2sql-api` settings ([#403](https://github.com/nadeem4/nl2sql/pull/403)). `NL2SQL_MODE` sets the mode when no flag does.
- **The state store gains saved answers and approval grants** ([#430](https://github.com/nadeem4/nl2sql/pull/430), [#410](https://github.com/nadeem4/nl2sql/pull/410)). *What to do:* third-party state stores add the new methods.
