# NL2SQL 0.1.1

<!-- summary:start -->

A fix release for 0.1.0: `nl2sql doctor`, the Docker demo and pipeline errors now work as documented, and the API image builds.

<!-- summary:end -->

*Released 2026-09-07.*

## Highlights

- `nl2sql doctor`, the command you run when something is wrong, no longer crashes.
- The Docker demo can reach its databases and survives a terminal that cannot show prompts.
- A question that no subgraph can answer ends with a clear error code, not a crash.
- The API image builds and is published to GHCR.

## What's included

### Fixes

- `nl2sql doctor` checks connectivity again instead of failing on an import ([#72](https://github.com/nadeem4/nl2sql/pull/72)).
- A secrets config with every provider commented out is read as "no secret providers", not an error ([#73](https://github.com/nadeem4/nl2sql/pull/73)).
- The Docker demo's datasources are reachable: only passwords are treated as secrets when a config is resolved ([#74](https://github.com/nadeem4/nl2sql/pull/74)).
- `nl2sql setup --demo --docker` no longer crashes under Git Bash on Windows ([#79](https://github.com/nadeem4/nl2sql/pull/79)).
- When no subgraph matches a question, the pipeline raises a real error ([#75](https://github.com/nadeem4/nl2sql/pull/75)), and its error code reaches the caller ([#78](https://github.com/nadeem4/nl2sql/pull/78)).
- The API image is built from the repository root, which fixes the GHCR publish that failed on 0.1.0 ([#70](https://github.com/nadeem4/nl2sql/pull/70)).

### Docs

- The docs match the code again ([#77](https://github.com/nadeem4/nl2sql/pull/77)).

## Known limits

- Tagging 0.1.1 did not publish it, because the PyPI upload failed in CI. The packages and the image went out about an hour later, by a manual re-run once the fix that shipped as 0.1.2 was on `main`.
- The project is pre-1.0, so the API can still change between minor versions.

## Upgrading

```console
pip install --upgrade "nl2sql-engine==0.1.1"
```

Breaking changes: none.
