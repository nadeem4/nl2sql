# NL2SQL 0.2.4

<!-- summary:start -->

A cache fix: a cached plan is now reused only on the day it was made, so a relative-date question such as "the last 30 days" is never answered with an earlier day's dates.

<!-- summary:end -->

*Released 2026-10-12.*

## Highlights

- "This year", "the last 30 days" and "yesterday" are planned against today's date, even when the same question was asked on an earlier day. Before this, the plan cache could serve an earlier day's plan with that day's dates.
- Every cached plan carries the date it was made, not only plans that look date-relative, because nothing reliably tells which plans depend on today. A plan is reused for the rest of that day, or for as long as `NL2SQL_TODAY` pins the date.

## What's included

### Fixes

- The plan cache key includes the run date ([#228](https://github.com/nadeem4/nl2sql/pull/228)).

## Known limits

- Each query returns at most 1,000 rows by default, and the answer model sees the whole result.
- "Rows 11 to 20" reaches the planner only through the question text.
- Questions across several databases are still limited.

## Upgrading

```console
pip install --upgrade "nl2sql-engine[demo]==0.2.4"
```

Breaking changes: none. Plans cached before the upgrade no longer match and are planned again once.
